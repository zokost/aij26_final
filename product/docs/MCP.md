# MCP: подключение агента

MCP — отдельный процесс stdio, обращающийся к работающему HTTP API. Он не загружает вторую GPU-модель и не получает ключ OpenRouter. HTTP-ручки `/mcp` нет.

## Установка на Linux

Из каталога комплекта:

```bash
mkdir -p inputs
uv venv --python python3 .venv-mcp
uv pip install --python .venv-mcp/bin/python -r requirements-mcp.txt
curl --fail http://127.0.0.1:8080/health
```

GPU-окружение находится в Docker; MCP устанавливается отдельно.

## Codex на том же сервере

Запускайте Codex из каталога комплекта:

```bash
codex mcp add aij-photo-review -- ./.venv-mcp/bin/python -m app.mcp_server --image-root ./inputs --api-url http://127.0.0.1:8080
codex mcp get aij-photo-review
```

Создайте `inputs/` и положите туда фотографии. Рабочий каталог MCP должен совпадать с каталогом комплекта; при настройке через интерфейс укажите его как working directory. После добавления перезапустите MCP; для текущего чата может понадобиться новая сессия.

## Codex на своём компьютере, сервис и MCP на сервере

Сначала скопируйте фотографии в `inputs/` на сервере. Путь установки задайте **относительно домашнего каталога SSH-пользователя**:

```bash
PROJECT_DIR='product'
codex mcp add aij-photo-review-remote -- ssh -T -p SSH_PORT USER@SERVER "cd '$PROJECT_DIR' && exec .venv-mcp/bin/python -m app.mcp_server --image-root ./inputs --api-url http://127.0.0.1:8080"
```

Замените каталог, SSH-порт и адрес своими значениями. Команда не привязана к Windows или абсолютному пути проекта. SSH-ключ должен работать без запроса пароля. `image_path` в этом варианте относится к файлу **на сервере** внутри `inputs/`.

Альтернатива: MCP на своём компьютере и SSH-туннель к API. Тогда адаптер читает местные фотографии и отправляет их удалённому детектору. Для облачного агента фото, маска и наложение также попадут провайдеру его VLM.

## Инструменты

| Инструмент | Аргументы | Результат |
|---|---|---|
| `service_status` | — | Готовность и параметры API |
| `analyze_image` | `image_path` | Детекция, `analysis_id` и области |
| `get_analysis_views` | `analysis_id` | Три изображения: фото, маска и жёлтое наложение |
| `explain_region` | `analysis_id`, `region_id` | Платная подсказка Together, кеш повторного ответа |

Пример запроса агенту:

> Проверь файл photo.jpg через aij-photo-review. Сначала проверь готовность, затем получи анализ и три изображения. Опиши видимое в выделенной области и ограничения вывода. Платное пояснение не вызывай.

Отдельно:

> Запроси пояснение Together для области 1 этой проверки. Покажи подсказку и стоимость.

Порядок: `service_status → analyze_image → get_analysis_views`; затем при необходимости `explain_region`. Жёлтая подсветка искусственная; оценивайте цвет и фактуру по чистому фото. Тип операции и доказанная причина изменения не устанавливаются.

## Ограничения и проверка

- Только файлы внутри `--image-root`, без выхода через `..` или символические ссылки; JPEG/PNG/WebP до 20 МиБ и 15 млн пикселей.
- Последние 20 проверок, до 128 МиБ фото/масок в памяти MCP. У API независимый кеш последних 20 проверок. После вытеснения или перезапуска повторите анализ.
- API-адрес адаптера — loopback HTTP; удалённый доступ организуется SSH-туннелем или запуском stdio через SSH.
- MCP не управляет видео и обращениями браузера. У `cached=true` стоимость относится к первому запросу.

```bash
.venv-mcp/bin/python -m unittest discover -s tests -p 'test_mcp_server.py' -v
```

Тесты не используют GPU или платные запросы. Схема настройки Codex: [официальная документация](https://developers.openai.com/codex/mcp/).
